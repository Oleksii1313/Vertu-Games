# VertGames: запуск и подтверждение почты

## Вход через Google

Добавлен отдельный вход без пароля сайта и без SMTP: **[GOOGLE_AUTH_SETUP.md](GOOGLE_AUTH_SETUP.md)**. Для активации нужны стабильный HTTPS-origin, сервер, зависимости `requirements.txt` и собственный OAuth web client Google. Старые аккаунты привязываются из профиля после входа прежним способом; email сам по себе не объединяет записи. Ключей в архиве нет.


## Что теперь работает без дополнительных файлов

Каждая игра в `games/*.html` самодостаточна. Её код, оформление, сенсорные кнопки и необходимые библиотеки встроены в HTML. Для запуска самой игры не нужны CDN, файлы JS/CSS, npm или сервер аккаунтов. MiniCraft и Chef’s Rover требуют WebGL 2.

При запуске игры из каталога награды передаются родительской странице. Открытие HTML отдельно не подключает его к балансу каталога.

## Почему раньше не получалось войти

1. При входе по email проверка находила пользователя, но страница сохраняла **email вместо канонического ника** в сессии. Профиль затем не находился. Исправлено на всех четырёх страницах.
2. Старые аккаунты хранились только в `localStorage` конкретного браузера и адреса сайта. Другой домен/порт, устройство, приватный режим, очистка данных или изолированный предпросмотр не имеют доступа к этому хранилищу.
3. Ошибка записи могла подавляться, а регистрация показывала успех. Теперь локальная регистрация при недоступном постоянном хранилище не сообщает об успехе.

Старые записи не удалены. Можно войти по нику (без учёта регистра) или email и прежнему паролю. Если запись отсутствует в текущем браузере/адресе, автоматически восстановить её из другого хранилища невозможно.

## Серверная регистрация с настоящим письмом

Регистрация письмом в `server.py` использует стандартную библиотеку Python и SQLite, без дополнительных зависимостей. Только для нового Google-входа установите `requirements.txt`. При обновлении рядом с `server.py` также должен находиться модуль `google_oauth.py`.

1. Скопируйте `.env.example` в `.env`.
2. Укажите параметры своего SMTP-сервиса:
   - `SMTP_HOST` — адрес SMTP-сервера;
   - `SMTP_PORT` — обычно `587` (STARTTLS) или `465` (SSL);
   - `SMTP_MODE` — `starttls` или `ssl`;
   - `SMTP_FROM` — разрешённый сервисом адрес отправителя;
   - `SMTP_USER` и `SMTP_PASSWORD` — учётные данные сервиса / пароль приложения;
   - `PUBLIC_URL` — точный публичный адрес сайта, например `https://games.example.com`.
3. На Linux/macOS запустите из папки проекта:

```bash
set -a
. ./.env
set +a
python3 server.py
```

На Windows установите те же переменные среды перед `python server.py`.

Откройте сайт через этот сервер (по умолчанию порт 8000). Для публикации используйте HTTPS и обратный прокси на этот же сервер. `/api/auth/*` и страницы должны быть на одном origin; отдельный статический хостинг сам письма отправлять не сможет.

**Не отправляйте SMTP-пароль в чат и не публикуйте `.env`.** Настройки добавлены в `.gitignore`, сервер не выдаёт их через HTTP.

**В текущем проекте реальные SMTP-реквизиты не настроены.** До настройки новые регистрации честно показывают ошибку отправки/конфигурации и не создают аккаунт. Вход в уже существующие локальные аккаунты от SMTP не зависит.

## Поток регистрации

- Проверяются формат почты, ник, совпадение паролей и уникальность учётной записи.
- Письмо содержит шестизначный код, действующий 10 минут.
- До верного кода аккаунт не создаётся и вход не разрешается.
- После пяти неверных кодов требуется новое письмо. Повторная отправка доступна не чаще раза в минуту. API ограничивает частоту запросов.
- Пароли на сервере сохраняются как PBKDF2-SHA256 с индивидуальной случайной солью, не открытым текстом. Сессия — случайный токен в HttpOnly/SameSite cookie; сервер хранит только хеш токена.
- Код не показывается на сайте, не возвращается API и не выводится в журналы сервера.

## Как перенести старый аккаунт

1. Откройте **тот же адрес сайта в том же браузере**, где он создавался.
2. Войдите по старому нику/email и паролю.
3. Откройте профиль → **«Подтвердить почту и сохранить аккаунт на сервере»**.
4. Повторите пароль и введите код из письма.

После подтверждения вход доступен и из другого браузера через сервер. Если ник/email уже принадлежат подтверждённой серверной записи, вместо создания дубля используйте серверный вход.

**Важно:** этот сервер переносит и хранит идентичность аккаунта, пароль и подтверждение почты. Баланс, покупки, профиль и таблица лидеров пока остаются в прежнем браузерном хранилище. При подтверждении существующего аккаунта они сохраняются в этом браузере; автоматически синхронизировать их между устройствами сервер пока не умеет. Защищённая серверная экономика и серверное администрирование — отдельная задача; существующая клиентская админ-панель не управляет таблицей серверных учётных записей.

## Хранение и обслуживание

- База учётных записей: `data/accounts.sqlite3`. Сохраняйте этот каталог между перезапусками и развёртываниями.
- Резервную копию делайте через SQLite Backup API либо после остановки сервера; не копируйте только основной файл во время записи в WAL.
- `database.js` — совместимость со старыми аккаунтами и локальными данными игр.
- `auth-client.js` — интерфейс входа, регистрации и ввода кода.
- Оба клиентских модуля встроены в HTML страниц. После изменения их исходников выполните `python3 tools/sync_auth.py`.

## Камера MiniCraft

На компьютере «Играть»/«Продолжить» запрашивает Pointer Lock: курсор скрывается, камера получает относительные движения мыши и не упирается в края экрана. Esc освобождает курсор и ставит игру на паузу. Если первый запрос отклонён, кнопка **«Захват мыши»** позволяет повторить запрос новым кликом.

На телефоне сохраняются свайп-обзор и джойстик. Запрещённый захват не запускает бесконечную автопаузу. Изолированный предпросмотр/родительский sandbox может запрещать Pointer Lock — страница не может обойти этот запрет. В таком случае доступен обзор с зажатой ЛКМ; для настоящего захвата откройте сайт в обычной вкладке браузера.

## Проверки

Проверены: девять HTML-игр без внешних запросов, вход/перезагрузка/дубли/неверный пароль на четырёх страницах, миграция старого аккаунта с сохранением локального баланса, вход из чистого браузера, реальный SMTP-протокол с изолированным тестовым приёмником, неверный/истёкший код, ограничения попыток и повторов, отсутствие ложного успеха без SMTP. Тестовый приёмник не отправлял письма в интернет и не подключён к рабочему серверу.
