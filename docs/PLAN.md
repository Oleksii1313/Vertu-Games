# VERTU GAMES — план полного обновления

Документ описывает, что именно меняется в проекте, в каком порядке и как проверяется.
Авторитетный источник по данным — сервер; браузер больше не хранит баланс.

## 0. Что было изучено

* `server.py` — stdlib HTTP-сервер: статические файлы + `/api/auth/*`, `/api/shop/*`,
  почтовая регистрация (SMTP), Google OAuth, сессии в SQLite, rate-limit.
* `database.py` — SQLite: `users`, `sessions`, `pending`, `limits`, `coin_ledger`,
  PBKDF2-хеши (310 000 раундов).
* `casino_payments.py` — платёжные провайдеры (ЮKassa/Stripe/CryptoBot), заказы и
  вебхуки; монеты начислялись браузером через `claim`.
* `auth-client.js`, `database.js` — клиентский «сервер входа» и localStorage-база
  `nl_users` (аккаунты, баланс, покупки, сессия).
* `index.html`, `casino.html` + `casino-app.js`, `roulette.html`, `admin.html`,
  `top.html`, `about/support/api/privacy` — весь фронтенд (слоты и колесо считаются
  в браузере, админка защищена `localStorage`-хешем пароля `219384`).
* `games/*` — 11 самостоятельных игр; общаются с каталогом через `postMessage`
  (`addCoins`, `skyDeliveryReward`, `redlineExchange`, `roverPenalty`, `gameOver`,
  `home`) и получают ник через `parent.getCurrentUser()`.

Вывод: игры и их контракт `postMessage` не трогаем. Меняем слой аккаунтов/экономики,
казино, магазин, админку и дизайн.

## 1. Данные: PostgreSQL (`DATABASE_URL`)

Новый слой `db.py` (единый API + миграции, транзакции, идемпотентность) и два драйвера:

* `store_pg.py` — PostgreSQL через `psycopg` (пул соединений), используется если задан
  `DATABASE_URL`;
* `store_sqlite.py` — SQLite для локального запуска и тестов (та же схема, те же
  запросы: `?` → `%s`).

Таблицы: `users`, `sessions`, `coin_ledger` (+ уникальный `ref`), `game_stats`,
`game_receipts`, `game_limits`, `shop_items`, `purchases`, `achievements`,
`user_achievements`, `casino_bets`, `casino_limits`, `admin_log`, `admin_sessions`,
`shop_orders`, `shop_ledger`, `platform_settings`, `rate_limits`, `schema_migrations`.

Инварианты:

* баланс меняется только в `db.add_coins()` внутри транзакции (`SELECT … FOR UPDATE`,
  `MAX(0, …)`), каждая операция пишет строку в `coin_ledger`;
* `coin_ledger.ref` уникален → повторный запрос/вебхук/квитанция не начисляет дважды;
* клиент не может прислать себе монеты: суммы определяет сервер.

Миграция существующих данных: `tools/migrate_legacy.py` переносит `data/accounts.sqlite3`
(ники, PBKDF2-хеши, балансы, ledger) в PostgreSQL.

## 2. Аккаунты

* Регистрация: ник + пароль (8–128 симв.), без e-mail, без подтверждения почты.
* Ник уникален без учёта регистра (`username_key`), PBKDF2-SHA256 + соль.
* Cloudflare Turnstile: проверка на сервере (`TURNSTILE_SECRET_KEY`), одноразовость
  токена, honeypot и минимальное время заполнения формы.
* Rate-limit: IP + ник, блокировка после N неудач, ответы без утечки существования ника.
* Сессии: случайный токен, в БД только SHA-256, `HttpOnly`, `SameSite=Lax`, `Secure` за
  HTTPS, TTL 30 дней, отзыв при смене пароля.
* Смена пароля, выход, «выйти на всех устройствах».

## 3. Экономика

Один серверный баланс на все страницы/устройства: начисления за игры (с серверными
лимитами и квитанциями), магазин, казино; история операций в профиле и админке.

## 4. Казино

`casino_logic.py` — единственное место, где считаются результаты:

* колесо: 7 секторов (x5, x3, x2, x1, x0.5, x0.25, x0), веса как в текущем UI;
* слоты: 3 барабана, веса и выплаты как в текущем `casino-app.js`, пара = 0.4 ставки;
* ставки 5/10/20/25/50/100, серверный лимит ставки, дневной лимит оборота/проигрыша,
  добровольное самоисключение, бесплатный спин раз в сутки;
* правила, RTP и вероятности показываются в интерфейсе;
* история ставок/выигрышей — из `casino_bets`.

## 5. Магазин

Каталог предметов на сервере (`shop_items`): аватары, цвета, титулы, одноразовые
бонусы. Покупка — серверная транзакция с квитанцией, экипировка — настройки профиля.
Пакеты V-монет (реальные деньги) остаются выключенными по умолчанию (`SHOP_PROVIDER`
не задан) и теперь начисляются на сервере.

## 6. Админка

* Права — только в БД (`users.is_admin`) + серверная админ-сессия по паролю
  (`ADMIN_PASSWORD`, по умолчанию прежний `219384`), TTL 2 часа, журнал в `admin_log`.
* Пользователи: поиск, профиль, баланс (+/-/установить), бан/разбан, история.
* Статистика платформы, игры (вкл/выкл), казино (лимиты, вкл/выкл), журнал действий.

## 7. Дизайн

Единая дизайн-система `assets/vg/css/platform.css` (тёмный премиальный стиль, стекло,
градиенты, типографика, адаптив) + компоненты `assets/vg/js/*`: шапка с балансом,
тосты, модальные окна, скелетоны загрузки. Все страницы собираются из одного шаблона.

## 8. Проверка

`tools/check_platform.py` — сквозные проверки на реальном запуске: регистрация,
вход/выход, CAPTCHA, уникальность ника, сохранение баланса после перезапуска,
магазин, начисления, колесо/слоты, защита API, админка. Плюс ручная проверка страниц
на десктопе и телефоне.

### Мост к играм (важное решение)

Игры не переписывались. Они по-прежнему шлют `postMessage`, но теперь родительская
страница **не доверяет сумме из сообщения**: она отправляет на сервер `{game, receipt}`,
а `POST /api/games/reward` берёт награду из `game_catalog.py`, проверяет суточный лимит
и уникальность квитанции. Ответ на `skyDeliveryReward`/`redlineExchange` содержит
`ok` только если монеты реально начислены. Гость (`getCurrentUser()` → `null`) играет
без наград. Сообщения с чужим `origin` игнорируются.

### Ограничения, о которых честно сказано в UI

* Казино — только виртуальные V; покупка монет за деньги отключена
  (`/api/shop/packs` возвращает `configured: false` без провайдера).
* Если Turnstile не настроен владельцем, сервер работает без капчи, но об этом
  сообщает `/api/health` и `TURNSTILE_REQUIRED=1` превращает это в ошибку старта.
