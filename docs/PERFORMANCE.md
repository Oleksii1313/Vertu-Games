# Лёгкий режим и производительность

Короткий ответ: сайт **сам** включает облегчённый режим на слабых устройствах и
**никогда не удаляет** игры, функции или контент — только отключает дорогие
эффекты (размытие подложки, тени, постоянные анимации) и снижает плотность
рендера. На нормальном железе всё остаётся как было.

## Как включить вручную

| Адрес | Что делает |
|---|---|
| `https://<сайт>/?perf=low` | принудительно лёгкий режим, даже на мощном ПК |
| `https://<сайт>/?perf=high` | принудительно обычный режим, даже на слабом |
| `https://<сайт>/` | автоматически решает по устройству |
| `https://<сайт>/games/sky-isle.html?perf=low` | лёгкий режим сразу для игры |

Настройка запоминается в адресе страницы и передаётся в игры: платформа
добавляет `&perf=low` к адресу `<iframe>`.

## Когда режим включается сам

```js
saveData === true                     // включён режим экономии трафика
deviceMemory <= 4                     // ≤ 4 ГБ ОЗУ
hardwareConcurrency <= 2              // ≤ 2 логических ядра
```

Любое из условий → атрибут `data-lowend="1"` на `<html>`, класс `low-end` на
`<body>`. Проверить в браузере: F12 → Elements → тег `<html>`.

## Что именно меняется

**CSS** (`assets/vg/css/platform.css`, блок «лёгкий режим»):

* шапка, панель игрока и меню теряют `backdrop-filter` (самый дорогой эффект
  для слабых видеокарт) и глубокие тени;
* останавливаются постоянные декоративные анимации (орбы, блики, пульсация);
* блоки вне экрана (`content-visibility:auto`) не раскладываются заранее —
  длинный каталог скроллится без рывков.

**Игры** — только плотность пикселей, механика не меняется:

| Игра | Обычно | `perf=low` |
|---|---|---|
| 2D (pong, platformer, shooter, 2048) | 2.5× CSS-пикселя | 1.5× |
| flappy, snake, doodle | 2–3× | 1.5× |
| sky-isle | 1:1 (физические пиксели) | 1.5 (меньше пикселей) |
| redline | dpr/2 на телефоне, 1 на ПК | 1.5 |
| chefs-rover | до 2× | 1.25× |
| minicraft | до 2× | 1.25× |

Резкость (высокая плотность) — это отдельная задача, она работает всегда:
2D-игры рисуют в 2.5× физических пикселя, 3D-игры — в физических пикселях
экрана, а не в CSS-пикселях.

## Полный экран на телефоне

При открытии любой игры на устройстве с тач-экраном плеер сам просит настоящий
полный экран (`requestFullscreen({navigationUI:'hide'})` на оверлее игры):
адресная строка с названием сайта и боковые кнопки браузера убираются. При
выходе из игры полноэкранный режим снимается.

Браузеры разрешают такой запрос только из действия пользователя (тап по
карточке игры) — это и есть открытие игры, поэтому запрос проходит. Если
браузер отказал (например, iOS Safari не поддерживает Fullscreen API для
произвольных элементов), включается запасной вариант `pseudo-full`: оверлей
занимает весь видимый экран с учётом `100dvh` и safe-area. Кнопка
«На весь экран» в панели игрока работает как раньше.

## Изображения каталога

`loading="lazy"` + `width`/`height` у картинок: браузер не грузит превью за
пределами экрана и не «прыгает» раскладкой. Никакие изображения не удалены.

## Тесты

```bash
NODE_PATH=/tmp/dom/node_modules node tools/test_perf_lowend.js       # 22/22
NODE_PATH=/tmp/dom/node_modules node tools/test_canvas_sharpness.js  # 38/38
NODE_PATH=/tmp/dom/node_modules node tools/test_play_overlay.js      # 35/35
```

`test_perf_lowend.js` проверяет: определение слабого устройства,
`?perf=low|high`, `data-lowend`, наличие правил CSS, снижение плотности во всех
играх, ленивую загрузку картинок и то, что **все 11 игр на месте**.

## Если что-то стало медленным

1. Откройте `?perf=high` — если стало быстро, дело в самом облегчённом режиме,
   напишите нам.
2. Откройте `?perf=low` — если наоборот стало быстрее, устройство просто
   слабое, всё работает как задумано.
3. F12 → Network → «Disable cache» и посмотрите размер картинок каталога.
