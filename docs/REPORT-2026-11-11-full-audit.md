## 1. Полноэкранный режим во всех 11 играх

Проверено по всем `games/*.html`: `100dvh` + `env(safe-area-inset-*)` +
класс `vg-landscape-fullscreen` есть в каждой игре; `viewport-fit=cover` — во
всех реальных страницах (`index`, `profile`, `casino`, `shop`, `admin`,
11 игр). Кнопка выхода и панели управления не перекрывают поле: они вне
canvas-рамки, поле занимает остаток высоты.

Отдельно исправлена причина «поле шире экрана» в `pong`: `resize()` считал
ширину от `window.innerWidth`, хотя вокруг поля есть панели; в iframe-плеере это
давало лишнюю ширину и растяжение картинки. Теперь размер берётся у самого
canvas (`getBoundingClientRect()` с запасными вариантами `clientWidth` →
`innerWidth` для первого кадра, когда layout ещё не посчитан).

## 3. Flappy Bird

Поле 360×(560…1100) в логических координатах, `viewDpr = min(2.5, dpr)`,
`ctx.setTransform(scale * dpr)` — пропорции сохраняются в портрете и

## 4. Качество графики: canvas, DPR, CSS vs физические размеры

**Причина «мыла» была не в CSS, а в буфере canvas.** На телефоне с DPR 3
браузер растягивал буфер размером в CSS-пиксели в 3 раза — отсюда размытые
линии, текст и края.

2D-игры (правки точечные, логика не тронута):

| Игра | Что сделано |
|---|---|
| `pong.html` | логические `VW/VH`, буфер `VW×min(2.5,dpr)`, `ctx.setTransform(dpr)`, ширина от canvas |
| `platformer.html` | выделен `fitBuffer()`, все игровые координаты — логические, буфер × DPR |
| `shooter.html` | то же; маппинг указателя переведён на логические `VW` |
| `game2048.html` | логическая сетка `BOARD=560`, буфер `560×min(2.5, css×dpr/560)`, отрисовка в координатах сетки |
| `snake`, `doodle`, `flappy` | уже были корректны — проверено тестом, не менялись |

3D-игры:

| Игра | Было | Стало |
|---|---|---|
| `sky-isle` | `adaptToDeviceRatio:false`, `setHardwareScalingLevel(max(1, dpr/1.4))` — рендер ниже CSS | `adaptToDeviceRatio:true`, `setHardwareScalingLevel(max(1, dpr/2))` |
| `redline` | `adaptToDeviceRatio:false`, `dpr/1.35` — рендер ~45 % CSS | `adaptToDeviceRatio:true`, `dpr/2` |
| `chefs-rover` | `min(dpr, 1.65)` | `min(dpr, 2)` |
| `minicraft` | `min(dpr, 1.75 / 1.5)` | `min(dpr, 2 / 1.75)`, адаптив сохранён |

Плотность выше 2× сознательно не включается: 3× вчетверо дороже 1.5× по числу
пикселей, а разницы на телефоне не видно.

Новый тест `tools/test_canvas_sharpness.js` (36 проверок) запускает игры в jsdom
с DPR 3 и проверяет **фактический** буфер после `resize()`: размер в физических
пикселях, коэффициент `setTransform`, отсутствие искажения пропорций, плотность
≥ 2× и отсутствие ошибок JS. Для WebGL-игр проверяются настройки плотности в
исходниках (jsdom WebGL не поднимает).

## 5. Аудит казино

Код-аудит без изменения ставок, множителей и выплат; регрессий не найдено,
всё уже сделано на сервере:

* ставка и выплата — одна транзакция с блокировкой кошелька (`SELECT … FOR UPDATE`),
  отрицательный баланс невозможен (`after < 0`), потолок `MAX_BALANCE`;
* идемпотентность по `reference_id`: `bet:<ref>` и `win:<ref>` в
  `casino_history`, повтор запроса возвращает `{repeated: true}` **до** проверки
  лимитов, поэтому двойное списание после refresh/retry невозможно;
* серверный расчёт результата: клиент присылает только игру и ставку;
* лимиты: `min_stake`/`max_stake`, `casino_limits.daily_limit`,
  `casino_limits.exclude_until`, `wheel_paid_daily = 5`, флаг `casino_enabled`
  и `{game}_enabled`;
* история и баланс читаются из БД, а не из состояния страницы, поэтому после
  refresh сходятся.

Проверено тестами: `test_economy` 18/18, `test_anticheat` 25/25,
`test_admin_secure` 20/20, `test_captcha` 17/17, `test_wheel_math` 10 098
проверок (математика колеса), `tools/check_platform.py` 261/261.

## 6. Аудит монетных наград

* Игра отправляет только «единицы» (`units`), сумму считает сервер по ставке
  каталога — подделать сумму из клиента нельзя;
* `game_reward` идемпотентен: `game_receipts.ref` — первичный ключ, повтор
  возвращает ранее начисленное без второго начисления;
* суточные лимиты `game_limits(user_id, game_id, day)` и статистика
  `game_statistics` в той же транзакции;
* клиент (`VGReward`) генерирует `sessionId = 'run-<game>-…'`, при отсутствии
  ответа за 9 с переходит в `failed` и повторяет с тем же `sessionId`;
  незавершённые сессии не начисляются, `localStorage['vg_pending_<game>']`
  даёт дослать награду после перезагрузки;
* платформа клампит `units ≤ 500` и `time ≤ 3600` до отправки;
* уведомление и сумма в оверлее берутся из ответа сервера (`awarded`,
  `capped`, `zero`), а не из локального счёта.

## 7. Контролы Sky-Isle — что было и как починено

Две настоящие причины, обе в игре (не в `platform.js`):

1. **Потеря клавиш.** Обработчик `keydown` вызывал `e.target.matches(...)`.
   Событие, пришедшее из платформы/`document`, имеет `target` без `matches` →
   `TypeError` в каждом нажатии, обработчик падал целиком. Заменено на
   `const t=e.target; if(t&&t.matches&&t.matches('input,textarea,select'))return;`
   — фокус в поле ввода по-прежнему не ломает игру, но падения нет.
2. **Сброс джойстика.** На `resize` вызывался `clearInput()`, а мобильный Safari
   шлёт `resize` при схлопывании адресной строки — джойстик отпускался в
   середине движения. Теперь `resize` только `engine.resize()`, ввод не
   сбрасывается.

Тест `tools/test_sky_controls.js` (18/18) проверяет именно это: клавиши из
`document`, клики по кнопкам, touch/pointer на джойстике, отсутствие исключений
в консоли, сохранение ввода при `resize`, работу после рестарта. Прежний
`test_sky_logistics.js` (33/33) проходил и при сломанных контролах — поэтому он
доказательством не считается.

языка проверены `tools/test_mobile_layout.js` (36/36), `test_header_tiles`

Горизонтального скролла нет: проверено отсутствие фиксированных ширин больше

## 9. Производительность и утечки

* Слушатели `resize`/`pointerdown`/`visibilitychange` навешиваются один раз при
  загрузке — накопительных подписок в повторных `start()`/`reset()` нет
  (проверено по всем 2D-играм).
* Все игры ставят цикл на паузу по `visibilitychange` — фон не жжёт батарею.
* Массивы эффектов ограничены: `trail` в `pong` ≤ 12, пули/враги/пикапы
  фильтруются по выходу за поле каждый кадр, частицы живут по времени жизни.
* 3D: один экземпляр движка на страницу, `preserveDrawingBuffer` только там, где
  нужен скриншот; `minicraft` снижает плотность шагом 0.25 при кадре > 26 мс.
* Двойной буфер больше не пересоздаётся на каждый кадр — размеры меняются
  только при фактическом изменении (`if (c.width !== bw …)`), иначе браузер
  переаллоцировал бы память и сбрасывал контекст 60 раз в секунду.

## 11. Что осталось / риски

1. Ручной прогон чек-листа на Android Chrome и iOS Safari (пункт 10) —
   автоматика покрывает код и структуру, но не реальный рендеринг.
2. `100svh` не используется нигде: опираемся на `100dvh`. Это осознанно (dvh
   даёт «настоящий» экран), но на iOS возможен один resize при скрытии
   адресной строки — джойстик Sky-Isle это уже переживает, остальные игры
   пересчитывают размер без потери ввода.
3. `chefs-rover.html` — минифицированная сборка без `.cache/rover-runtime.js`
   в репозитории, поэтому пересобрать её здесь нельзя; правка внесена в
   исходник `games/chefs-rover.js` и в собранный файл одинаково (проверяется
   тестом на совпадение).
4. `redline.html`, `sky-isle.html`, `minicraft.html` — генераты; правки
   внесены и в исходники, и в артефакты. Полная пересборка `sky-isle`
   запрещена: шаблон без `data-ru/data-en`, пересборка молча удаляет переводы.
