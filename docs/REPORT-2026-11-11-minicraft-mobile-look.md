# MiniCraft 3D: обзор камеры пальцем на телефоне — причина и исправление

Дата: 11.11.2026 · ветка `arena/a0cae9b6-vertu-games` · игра: `games/minicraft.html`
(на сайте — https://vert-games.onrender.com/games/minicraft.html)

Жалоба: при перетаскивании по экрану камера прыгает и крутится бесконтрольно, экран
дёргается и «теряет фокус». Нужен нормальный мобильный обзор: слева джойстик, справа
свайп — как в Minecraft PE; движение и обзор одновременно; десктоп не менять.

---

## 1. Что было на самом деле

Камера поворачивается ровно в одном месте — `Qh()` (прибавляет к `F.yaw`/`F.pitch`
приращение, умноженное на чувствительность). Ни физика, ни анимации, ни мир камеру не
трогают: это проверено поиском по файлу — `F.yaw`/`F.pitch` меняются только в `Qh`.
Значит «бесконтрольное вращение» — это не баг рендера, а мусор во **входных данных**.

Весь тач-обзор до правки — это один слот состояния `yt` и три функции на холсте:

```js
Kg  (pointerdown)  → if (yt) return;              // вся площадь экрана, один слот
jg  (pointermove)  → Qh(dx * 1.5, dy * 1.5);      // множитель мыши приклеен и к пальцу
Qg  (pointerup)    → yt = null
```

### Воспроизведение (jsdom, настоящий рантайм игры, WebGL заменён заглушкой)

Замеры на исходном коде, экран 390 × 844 (телефон в портрете), обычные события
`pointerdown/pointermove/pointerup` с `pointerType: "touch"`:

| Сценарий | Что видел игрок |
|---|---|
| Свайп 120 px | камера ушла всего на **0.36 рад = 20.6°** (0.00300 рад/px ≈ 0.17°/px). Свайп по всей ширине экрана — **67°**. Камера «не слушается», хочется вести палец быстрее и дальше |
| Один `pointermove`, где браузер прислал `clientX/clientY = 0` (так он сообщает о потерянном указателе и об отмене жеста) | мгновенный рывок **+0.630 рад = 36°** |
| `pointerup` потерялся (жест перехватил системный интерфейс / окно потеряло фокус), затем новый палец получил тот же `pointerId` | камера стоит (новые касания глотаются: `if (yt) return`), а на первом же движении — рывок **0.720 рад = 41°**, потому что дельта считается от давно протухшей точки |
| Пока `yt` «висит», любые новые касания холста | обзор не работает вообще — «камера перестала слушаться» |

Итог: причина не одна, а сочетание четырёх дефектов ввода — заниженная
чувствительность пальца, отсутствие проверок координат, единственный слот состояния без
привязки к реально нажатым пальцам и отсутствие `touch-action` на самом холсте (браузер
вправе забрать жест на прокрутку/жест-навигацию и прислать `pointercancel` посреди
свайпа — отсюда «экран уезжает / страница перезагружается / игра встаёт на паузу»).

## 2. Что исправлено

Правки — только в системе ввода камеры `games/minicraft.html` (и один CSS-блок).
Графика, текстуры, блоки, мир, карты, анимации, физика, геймплей, интерфейс, позиции
кнопок, десктопное управление — не тронуты.

### 2.1. У пальца своя чувствительность

```js
MCX_LOOK_SENS  = .002,     // мышь (как было)
MCX_LOOK_DRAG  = 1.5,      // множитель мыши без захвата (как было, = 0.003 рад/px)
MCX_LOOK_TOUCH = .0075,    // палец: 0.43° на пиксель
```

`Qh(i, e, sens)` получил необязательный третий параметр: у мыши поведение и цифры
прежние (0.003 рад/px при перетаскивании, 0.002 рад/px в захвате курсора), у пальца —
0.0075 рад/px. Свайп по ширине телефона теперь даёт ~168° (было 67°), свайп 120 px —
51.6° (было 20.6°): поворот «на глаз» без длинных размашистых движений.

### 2.2. Защита от рывков на сбойных событиях

`mcxTouchLookSample()` отбрасывает то, что не может быть движением пальца:

* нечисловые координаты (`NaN`) — пропуск;
* событие с `clientX === 0 && clientY === 0` — пропуск (следующее настоящее событие
  посчитается от прежней точки, поэтому движение не теряется);
* скачок больше **240 px**, пришедший меньше чем за **24 мс** (это > 10 000 px/с —
  физически невозможно) — пропуск с переснятием отсчёта;
* честный быстрый флинт (большое расстояние, но нормальный интервал) не теряется, а
  ограничивается 240 px за событие.

Плюс `getCoalescedEvents()`: браузер отдаёт все промежуточные точки, поэтому быстрый
свайп остаётся плавным и точным, а не «шагами».

### 2.3. Состояние привязано к реальным касаниям

* `mcxTouches` (`Set` из `pointerId`) ведётся на `document` в capture-фазе для
  `pointerdown/pointerup/pointercancel`, очищается в `po()` (пауза, blur, смена
  ориентации).
* На `pointerdown` обзор всегда начинается с новой точки. Браузер не присылает
  `pointerdown` для пальца, который уже на экране, — значит повторный `pointerdown` с
  тем же `pointerId` это гарантированно новый жест (или потерянный `pointerup`), и
  старый отсчёт переснимается. Рывка на 41° больше нет.
* Второй палец, пока первый ведёт обзор, обзор не перебивает — и наоборот, отпускание
  «чужого» пальца не сбрасывает камеру (`Qg` и раньше сверяла `pointerId`, теперь это
  подкреплено набором активных касаний).

### 2.4. Явная зона обзора

`mcxInLookZone()` — обзор начинается на всей площади экрана, кроме площадки джойстика
(его прямоугольник + 18 px запаса) и элементов интерфейса. Кнопки, хотбар, панели,
сам джойстик перехватывают свои касания сами (`Kg` отсекает их по `closest()`), поэтому
Jump/Attack/Block камеру не крутят. Правая часть экрана, где лежит большой палец, —
основная зона обзора; левый нижний угол отдан движению.

### 2.5. Браузер больше не отбирает жест

В CSS добавлено:

```css
#viewport,#viewport canvas{touch-action:none;user-select:none;-webkit-user-select:none;
  -webkit-touch-callout:none;-webkit-tap-highlight-color:transparent}
```

`body{touch-action:none}` был и раньше, но `touch-action` считается по цепочке
предков, а на iOS Safari прокрутка/«pull-to-refresh» всё равно срабатывают, если у
самого затронутого элемента правило не задано. Теперь правило есть у холста —
браузер не забирает свайп на прокрутку и не присылает `pointercancel` посреди
обзора. `preventDefault()` вызывается и на `pointerdown`, и на каждом `pointermove`
пальца.

## 4. Десктоп не изменился

* ПКМ зажать и вести — обзор, 0.003 рад/px, знаки прежние (проверено по вектору взгляда).
* ЛКМ — удар/добыча, камеру не двигает; короткий клик ПКМ — блок.
* Захват мыши (`pointer lock`) — `mousemove` с `movementX/Y`, 0.002 рад/px,
  ограничение ±200 px за событие и прежняя защита 120 мс после захвата.
* `focus({preventScroll:true})`, подсказки, кнопка «Захват мыши» — как были.
* Мышь на «тач-раскладке» по-прежнему возвращает десктопный режим.

## 6. Ручная проверка на телефоне (2 минуты)

1. Открыть игру, создать мир, нажать «Играть».
2. **Джойстик** (слева снизу) — персонаж идёт; камера при этом не крутится.
3. **Свайп справа** — камера плавно идёт влево/вправо, вверх/вниз; за один свайп по
   ширине экрана — примерно пол-оборота.
4. **Два пальца**: держать джойстик и одновременно вести обзор — идёт и смотрит;
   отпустить один палец — второй продолжает работать.
5. **Attack / Блок + / Прыжок** — срабатывают как раньше и камеру не крутят.
6. Быстрые резкие свайпы, свайп от самого края экрана, свайп через весь экран —
   камера не прыгает, страница не прокручивается, не перезагружается и не выходит
   из игры, игра не встаёт на паузу.
7. Повернуть телефон (портрет ↔ ландшафт) — обзор и джойстик сразу работают.
8. На компьютере: ПКМ-обзор, ЛКМ-удар, короткий ПКМ-блок, «Захват мыши» — без
   изменений.
