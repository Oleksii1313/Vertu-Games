Your data, explained.

Что хранится на устройстве, что получает сервер и почему перенос входа не равен переносу игровых сохранений.

What stays on your device, what reaches the server and why transferring sign-in is not the same as transferring game saves.

Обновлено: 13 октября 2026 · RU / EN

Updated: 13 October 2026 · RU / EN

Ниже описано фактическое хранение данных в этой версии проекта, а не обещание полного соответствия всем правовым требованиям. Владелец пока не указал контакт для запросов по персональным данным. Перед публичным запуском ему нужно опубликовать сведения об операторе, контакт и правила хранения.This explains how this version stores data; it does not claim compliance with every legal requirement. The owner has not provided a personal-data contact. Before public deployment, they should publish operator details, contact information and retention rules.

01. Что остаётся в браузере

01. What stays in your browser

Каталог использует localStorage и sessionStorage. Там могут находиться выбранный язык, локальный профиль (ник и email), баланс, покупки, оформление, имя текущего пользователя, данные незавершённого подтверждения почты и сохранения игр. Старые локальные аккаунты могут содержать соль и хеш пароля; это не серверная схема PBKDF2.

The collection uses localStorage and sessionStorage. They may contain language, local profile data (username and email), balances, purchases, appearance, the current username, pending email-verification data and game saves. Legacy local accounts may contain a password salt and hash; that is not the server PBKDF2 scheme.

Основные ключи: nl_users, nl_current, nl_lang, vg_pending_email; игровые ключи зависят от игры и аккаунта. Локальные данные не синхронизируются между браузерами и доменами автоматически.

Main keys include nl_users, nl_current, nl_lang and vg_pending_email; game keys vary by game and account. Local data is not automatically synchronized across browsers or domains.

Очистка данных сайта может безвозвратно удалить локальные аккаунты, монеты и игровой прогресс. Выход из аккаунта не равен удалению этих данных.Clearing site data may permanently delete local accounts, coins and game progress. Signing out does not delete these data.

02. Данные сервера аккаунтов

02. Account server data

Если запущен сервер аккаунтов, его SQLite-база хранит ник, email, время создания/подтверждения и хеш пароля. Пароль преобразуется PBKDF2-SHA256 со случайной солью; серверная таблица пользователей не хранит открытый пароль. Незавершённая регистрация содержит хеш кода, срок действия и число попыток.

When the account server runs, its SQLite database stores username, email, creation/verification times and a password hash. Passwords use PBKDF2-SHA256 with a random salt; the server users table does not store plaintext passwords. Pending registrations store a code hash, expiry and attempt count.

Для ограничения запросов сервер хранит временные счётчики с хешированным ключом на базе видимого ему IP. Для сессий хранится хеш токена и срок действия. По сети к этому серверу при входе/регистрации передаются введённые поля, поэтому публичное размещение должно использовать HTTPS.

Rate limiting stores temporary counters keyed by a hash derived from the IP seen by the server. Sessions store a token hash and expiry. Submitted sign-in and registration fields are sent to this server, so public deployment should use HTTPS.

Google: отдельный способ входа

Google: an additional sign-in method

По нажатию кнопки сайт перенаправляет вас на accounts.google.com и запрашивает только openid и email. Доступ к письмам, Gmail API, контактам, диску и паролю Google не запрашивается. Google получает обычные сведения запроса и данные выбранного аккаунта; применяется его политика конфиденциальности. До нажатия эта интеграция не загружает Google-скрипты.

When you click the button, the site redirects to accounts.google.com and requests only openid and email. It does not request mail, Gmail API, contacts, Drive or your Google password. Google receives normal request metadata and information about the chosen account under its own privacy policy. This integration loads no Google scripts before you click.

Сервер хранит Google subject (постоянный идентификатор) и связь с аккаунтом. OAuth-секрет хранится только в окружении сервера. Коды и токены Google используются для проверки и не сохраняются в SQLite, localStorage или журналах приложения. Refresh token не запрашивается. На время попытки в SQLite сохраняются хеши state/nonce/привязки, PKCE verifier и сведения возврата; cookie привязки HttpOnly действует до 10 минут. Успешно обработанная попытка удаляется, просроченные записи очищаются при новом старте входа.

The server stores the Google subject (a stable identifier) and its account association. The OAuth secret remains in server configuration. Google codes and tokens are used for verification and are not retained in SQLite, localStorage or application logs. No refresh token is requested. During a flow, SQLite stores state/nonce/binding hashes, a PKCE verifier and return details; an HttpOnly binding cookie lasts up to 10 minutes. Consumed flows are deleted; expired records are cleaned when a new flow starts.

Выход завершает сессию VertGames, но не выполняет выход из самого Google. Отзыв доступа в настройках Google не удаляет запись VertGames и не гарантирует немедленное завершение уже выданной сессии сайта. Для удаления серверной связи пока нужен владелец установки. Хостинг/прокси следует настроить так, чтобы callback query не попадал в access-логи.

Signing out ends the VertGames session, not your Google session. Revoking access in Google settings does not delete your VertGames record or guarantee immediate termination of an already issued site session. Deleting the server association currently requires the deployment owner. Hosting/proxy access logs should exclude callback query strings.

03. Cookie и сроки хранения

03. Cookies and retention

Cookie vg_session нужна для серверного входа: HttpOnly, SameSite=Lax, до 30 дней. Атрибут Secure зависит от корректной HTTPS-конфигурации. Коды подтверждения действуют 10 минут; повторное письмо ограничено минутным интервалом.

The vg_session cookie supports server sign-in: HttpOnly, SameSite=Lax, for up to 30 days. Secure depends on correct HTTPS configuration. Verification codes last 10 minutes, with a one-minute resend cooldown.

У аккаунтов и локальных сохранений нет общего автоматического срока удаления в этой сборке. Очистка просроченных серверных записей выполняется отдельными действиями API, а не гарантированным фоновым расписанием. Резервные копии и срок хранения журналов зависят от владельца установки.

Accounts and local saves have no general automatic deletion deadline in this build. Expired server records are cleaned by certain API actions, not by a guaranteed background schedule. Backups and log retention depend on the deployment owner.

04. Внешние подключения

04. External connections

Страницы каталога, рейтинга, рулетки и администрирования подключают Google Fonts: провайдер шрифтов получает обычные технические данные сетевого запроса. Sky-Isle при сетевом запуске пытается загрузить Babylon.js с официального cdn.babylonjs.com; автономная копия также встроена. Отправка кода подтверждения идёт через SMTP-провайдера, выбранного владельцем: ему передаются адрес получателя и текст письма с кодом.

Collection, leaderboard, roulette and administration pages load Google Fonts, whose provider receives normal network request metadata. When online, Sky-Isle attempts to load Babylon.js from the official cdn.babylonjs.com CDN; an offline copy is embedded as well. Verification emails use the owner’s SMTP provider, which receives the recipient address and email containing the code.

Эти четыре информационные страницы не подключают сторонние шрифты, счётчики аналитики или рекламные скрипты. Проверка API запускается только по кнопке. Сам хостинг, прокси или инфраструктура публикации могут вести собственные журналы запросов; эта страница не управляет ими.

These four information pages do not load external fonts, analytics counters or advertising scripts. API checks only run on request. Hosting, proxies and publication infrastructure may maintain their own request logs; this page does not control them.

05. Отчёты об ошибках

05. Issue reports

Форма в разделе поддержки обрабатывает текст в браузере и предлагает скачать JSON или скопировать его. Серверного приёма заявок здесь нет. По вашему выбору добавляются версия браузера, размер окна, сенсорный ввод и доступность WebGL. Cookie, URL страницы, содержимое аккаунтов и сохранений не добавляются. Текст формы не сохраняется автоматически.

The support form processes text locally and offers a JSON download or copy. It does not submit server tickets. You may include browser version, viewport, touch input and WebGL availability. Cookies, page URLs, account contents and game saves are excluded. Form text is not saved automatically.

Перед передачей файла удалите из собственного описания пароли, коды, токены и лишние персональные сведения. Если вы отправляете отчёт по почте самостоятельно, дальнейшая обработка зависит от выбранного получателя и почтового провайдера.

Before sharing the file, remove passwords, codes, tokens and unnecessary personal information from your own description. If you email it yourself, further processing depends on the recipient and email provider.

06. Ваши действия

06. Your controls

  1. Можно пользоваться отдельными HTML-играми без серверной регистрации. У них остаются локальные сохранения.You can use standalone HTML games without server registration. They still have local saves.
  2. Выйдите через интерфейс аккаунта, чтобы завершить текущую серверную сессию. Это не удаляет запись пользователя.Sign out through the account interface to end the current server session. This does not delete the user record.
  3. Управлять cookie и локальными данными можно в настройках браузера → данные сайтов → адрес этой установки. Перед удалением учитывайте потерю несинхронизированного прогресса.Manage cookies and local data in your browser settings → site data → this deployment’s address. Consider the loss of unsynchronized progress before deleting it.
  4. Самостоятельное удаление серверного аккаунта и универсальный экспорт сохранений в текущей версии не реализованы. Для серверного удаления нужен владелец установки; очистка браузера не удаляет его SQLite-запись.Self-service server account deletion and universal save export are not implemented in this version. Server deletion requires the deployment owner; clearing browser data does not delete the SQLite record.
