Документация API.

API documentation.

Реальные методы сервера аккаунтов: регистрация, подтверждение почты, вход и сессия. Форматы запросов, ответы и ограничения текущей версии.

The actual account server endpoints: registration, email verification, sign-in and sessions. Request formats, responses and limits in the current version.

Обновлено: 13 октября 2026 · RU / EN

Updated: 13 October 2026 · RU / EN

Это документация существующего API аккаунтов. Публичного API монет, сохранений, платежей или ключей для сторонних приложений сейчас нет. API работает только там, где запущен server.py; статический хостинг сам его не создаёт.This documents the existing account API. There is no public API for coins, game saves, payments or third-party API keys. It only works where server.py runs; static hosting does not create it.

The button only calls GET /api/auth/session. Results are a safe summary: username and email are omitted. It changes nothing and does not test email delivery.

Формат запросов
Request format
Пути указаны относительно корня сервера. Для POST нужен Content-Type: application/json, JSON-объект и тот же origin, что у сайта. Максимальный размер тела — 16 384 байта. Сессия передаётся cookie, а не API-ключом.
Paths are relative to the server root. POST requires Content-Type: application/json, a JSON object and the same origin as the site. Maximum body size is 16,384 bytes. Sessions use a cookie, not an API key.
const response = await fetch('/api/auth/session', {
  credentials: 'same-origin',
  headers: { Accept: 'application/json' }
});
if (!response.ok || !response.headers.get('content-type')?.includes('application/json')) {
  throw new Error('Account API is unavailable');
}
const session = await response.json();
// Avoid logging session.user: it may contain an email address.
Методы аккаунтов
Account endpoints
GET/api/auth/session
Возвращает ok, emailConfigured, googleConfigured и user (объект или null). У вошедшего пользователя объект включает username, email, emailVerified, authSource, created и googleLinked.
Returns ok, emailConfigured, googleConfigured and user (an object or null). For a signed-in user it includes username, email, emailVerified, authSource, created and googleLinked.
GET/api/auth/availability?username=…&email=…
Проверка занятости имени/почты. Поля ответа: usernameTaken, emailTaken, emailValid. До 120 запросов в минуту по серверному лимиту.
Checks username/email availability. Response fields: usernameTaken, emailTaken, emailValid. Server rate limit: 120 requests per minute.
POST/api/auth/register
Поля: username, email, password. До проверки кода аккаунт не создан. При успешной отправке письма возвращает registrationId, email, expiresIn (600), resendAfter (60). Ник — 1–48 допустимых символов; пароль — 4–256 символов по текущей схеме. Выбирайте длинный уникальный пароль.
Fields: username, email, password. The account does not exist until the code is verified. Once the SMTP provider accepts the email it returns registrationId, email, expiresIn (600), resendAfter (60). Username: 1–48 valid characters; password: 4–256 under the current schema. Choose a long unique password.
POST/api/auth/verify
Поля: registrationId, code (строка из шести цифр). Создаёт подтверждённый аккаунт, устанавливает cookie и возвращает user. После пяти неверных кодов требуется повторная отправка.
Fields: registrationId, code (a six-digit string). Creates the verified account, sets the session cookie and returns user. After five incorrect codes, a resend is required.
POST/api/auth/resend
Поле: registrationId. Новый код действует 600 секунд; между письмами минимум 60 секунд. Ответ: ok, resendAfter, expiresIn.
Field: registrationId. New codes last 600 seconds; emails must be at least 60 seconds apart. Returns ok, resendAfter, expiresIn.
POST/api/auth/login
Поля: identifier (ник или email), password. Успех: ok, user и Set-Cookie. Ник/email сопоставляются без учёта регистра; пароль — с учётом. До 20 попыток за 15 минут.
Fields: identifier (username or email), password. Success: ok, user and Set-Cookie. Username/email lookup is case-insensitive; passwords are case-sensitive. Up to 20 attempts per 15 minutes.
POST/api/auth/logout
Тело: {}. Удаляет текущую серверную сессию и очищает её cookie. Не удаляет аккаунт, баланс или локальные сохранения.
Body: {}. Deletes the current server session and clears its cookie. It does not delete the account, balance or local saves.
Вход через Google
Sign in with Google
POST/api/auth/google/start
Поля: mode (login или link), next (index.html/top.html/roulette.html/admin.html), lang (ru/en). Обязателен Origin, совпадающий с PUBLIC_URL. Ответ: ok, url — адрес выбора аккаунта Google. Устанавливает HttpOnly cookie привязки попытки на 10 минут. До 30 стартов за 15 минут. Режим link требует текущей серверной сессии.
Fields: mode (login or link), next (index.html/top.html/roulette.html/admin.html), lang (ru/en). Origin must match PUBLIC_URL. Returns ok, url—the Google account-selection URL—and sets a 10-minute HttpOnly flow-binding cookie. Up to 30 starts per 15 minutes. Link mode requires a current server session.
GET/api/auth/google/callback
Redirect URI для Google, не для ручной отправки email/JWT. Проверяет одноразовый state, cookie, PKCE, подпись ID token, issuer, audience, срок, nonce и подтверждённый адрес. При успехе — сессия сайта и 303 обратно на разрешённую страницу. Ошибка — только фиксированный код google_error; токены не передаются странице.
Google redirect URI, not an endpoint for posting an email or JWT. Checks one-time state, cookie binding, PKCE, ID-token signature, issuer, audience, expiry, nonce and verified email. Success sets a site session and redirects with 303 to an allowed page. Errors return a fixed google_error code; provider tokens are never sent to the page.
Нужны зависимости из requirements.txt, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET и стабильный PUBLIC_URL. Настройка: GOOGLE_AUTH_SETUP.md. SMTP для Google не требуется. Поддерживаются Gmail и Google Workspace; внешние адреса Google подтверждаются старым способом — кодом из письма. Существующие записи не объединяются по email автоматически. Привязка выполняется из профиля с тем же адресом и не меняет ник/баланс.
Requires requirements.txt dependencies, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET and a stable PUBLIC_URL. See GOOGLE_AUTH_SETUP.md. Google does not require SMTP. Gmail and Google Workspace are supported; external Google-account email addresses use the existing emailed-code method. Existing records are not auto-merged by email. Explicit profile linking requires the same email and preserves the username/balance.
Основные ошибки: GOOGLE_NOT_CONFIGURED, GOOGLE_CANCELLED, GOOGLE_STATE_INVALID, GOOGLE_TOKEN_FAILED, GOOGLE_ACCOUNT_EXISTS, GOOGLE_LINK_EMAIL, GOOGLE_LINK_SESSION, GOOGLE_EMAIL_EXTERNAL. У аккаунта, созданного только через Google, пароль сайта отсутствует; вход по паролю отвечает GOOGLE_LOGIN_REQUIRED.
Common errors: GOOGLE_NOT_CONFIGURED, GOOGLE_CANCELLED, GOOGLE_STATE_INVALID, GOOGLE_TOKEN_FAILED, GOOGLE_ACCOUNT_EXISTS, GOOGLE_LINK_EMAIL, GOOGLE_LINK_SESSION, GOOGLE_EMAIL_EXTERNAL. Google-only accounts have no site password; password sign-in returns GOOGLE_LOGIN_REQUIRED.
Ошибки и ограничения
Errors and limits
Ошибки API имеют вид {ok: false, code, msg}. Не считайте один статус 200 доказательством работающего API: статический хостинг может вернуть HTML вместо JSON.
API errors have the shape {ok: false, code, msg}. A 200 status alone does not prove the API works: static hosting may return HTML instead of JSON.

Дополнительные лимиты: регистрация — 10/час; повтор письма — 10/час; проверка кода — 30/15 минут. Лимиты привязаны к IP, который видит сервер. Изменение или удаление аккаунта, восстановление пароля и синхронизация игр не имеют endpoint в этой версии.
Additional limits: registration 10/hour; resend 10/hour; code verification 30/15 minutes. Limits use the IP seen by the server. Account editing/deletion, password recovery and game synchronization have no endpoint in this version.
Запуск и безопасность
Deployment and security
  1. Запустите python3 server.py в корне проекта. Для публичного размещения используйте HTTPS и настройте PUBLIC_URL.Run python3 server.py from the project root. Use HTTPS and configure PUBLIC_URL for public deployment.
  2. Для писем настройте SMTP_HOST, SMTP_FROM и остальные параметры по .env.example. Секреты не размещайте в клиентском HTML или публичном каталоге.Configure SMTP_HOST, SMTP_FROM and other email settings using .env.example. Do not put secrets in client HTML or public folders.
  3. Cookie vg_session: HttpOnly, SameSite=Lax, до 30 дней. Secure включается при корректно определённом HTTPS. Межсайтовый доступ API не открыт.The vg_session cookie is HttpOnly, SameSite=Lax, with a lifetime of up to 30 days. Secure is enabled when HTTPS is correctly detected. Cross-site API access is not enabled.
  4. Клиентский модуль window.VA обслуживает локальные данные интерфейса. Это не защищённый серверный API баланса и не античит.The client-side window.VA module manages local UI data. It is not a secure server balance API or anti-cheat system.
